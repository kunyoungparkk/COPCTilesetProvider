# cesium-runtime

The only place in this library that touches CesiumJS. `COPCTilesetProvider.fromUrl(url, options)` (`provider.ts`) opens a COPC file, builds a synthetic 3D Tiles document from it, and installs a codec onto a real `Cesium3DTileset` before handing that tileset back inside the returned `COPCTilesetProvider` — a `scene.primitives.add(...)`-able object that delegates `update`/`updateForPass`/`prePassesUpdate`/`postPassesUpdate`/`destroy` to it, and adds `stats()`, `tileset`, and `extent` of its own. `ScheduledRangeResource` (`resource.ts`) intercepts every tile request Cesium's traversal makes and answers it from the budget instead of the network; `createCodec` (`codec.ts`) turns the bytes that interception admits into `Cesium3DTileContent`, installed onto the private `_runtimeContentCodec` slot (OVERVIEW §3, Decision 2). Point styling and classification filters are `Cesium3DTileStyle`'s job, untouched here.

## What Decision 2's early return shifts onto this module

Decision 2's codec branch is a fast path inside Cesium: reached, it returns before Cesium's own content classification ever runs. That skip is what makes handing back a decoded PNTS for bytes that arrived as LAZ possible at all, and it is also what shifts work from Cesium onto this module. Decision 2 names four fields the codec must set; `codec.ts` explains beside the assignments why two of them are set here and two are left as Cesium's own non-codec path would leave them for a document that declares no `3DTILES_metadata`.

1. **The synthetic tileset's content URIs must be absolute.** A Blob URL resolves relative references against itself, not against the COPC file's own origin, and Cesium's own `getAbsoluteUri` already assumes absolute input. `provider.ts`'s `validateTokenBase` checks the `tokenBase` every content URI is built from: an absolute URI with a scheme, ending in `/`, unchanged by URI normalisation — called once per `fromUrl`, on a value this module generates itself, so a caller never has to satisfy this directly.
2. **The codec sets the tile flags Cesium's classification would otherwise set.** `hasTilesetContent` is only ever set true inside `Cesium3DTile`'s own `preprocess3DTileContent`, the exact call the early return skips. `hasRenderableContent` is different: a tile with a content URI already constructs with it true, and that same block only ever turns it false. `createCodec` sets both explicitly for every tile it builds content for — `hasRenderableContent = true` for a point tile, which is belt-and-braces, and `hasTilesetContent = true` with `hasRenderableContent = false` for a hierarchy page expanded into an external tileset, which is not. Miss either of that second pair and the subtree never opens.
3. **`skipLevelOfDetail` is a tileset construction option, not a codec field.** Cesium's own JSDoc documents a `disableSkipLevelOfDetail` field on the codec, but nothing in the installed 1.143 source reads it. `provider.ts` passes `skipLevelOfDetail: false` (Decision 1: ADD refinement already carries full resolution at every depth, so there is no coarser level to skip past) straight to `Cesium3DTileset.fromUrl`'s own options instead.

## Limits worth knowing

Nothing under `src/` proves that any of this renders a point cloud. The suite here is Vitest against real `Cesium3DTileset`/`Resource`/`Model3DTileContent`/`Tileset3DTileContent` instances and an offline regression guard (`tests/cesium-contract.test.ts`) that reads the installed Cesium source directly — neither drives a browser or produces a pixel. `tests/cesium-boundary.test.ts` is narrower still: it only checks that Cesium stays reachable from `src/index.ts` and unreachable from everywhere else.

`COPCTilesetProviderOptions.spawnWorker` is required, not optional, because nothing in this module can build a `WorkerPort` on its own: that needs the self-contained Worker bundle the bundling sub-project has not shipped yet (OVERVIEW §5). A caller supplies the factory until then.
